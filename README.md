# LOLDOV Frontend

롤 리플레이 영상을 올리면 주요 장면을 찾아 코칭해 주는 웹 화면.

- 사이트: https://168-110-28-55.sslip.io
- 서버(API): [Backend](https://github.com/LOLDOV/Backend), 분석 파이프라인: [AI](https://github.com/LOLDOV/AI)

## 구성

```
coach/index.html       # 업로드·분석 진행·리포트·질의응답 웹 페이지 (Backend가 / 에서 제공)
report/template.html   # 정적 리포트 틀 (AI의 report/build_site.py 가 분석 데이터를 넣어 HTML 한 장으로 만든다)
```

빌드 도구 없이 HTML 파일 한 장으로 동작한다 (바닐라 JS, 차트는 SVG로 직접 그림).
다크/라이트 모드는 시스템 설정을 따르고, 모바일 화면에도 맞춘다.

## 화면

**홈**

- 영상 업로드: 끌어다 놓기 또는 파일 선택 (MP4·WEBM·MKV·MOV, 최대 4GB). 큰 영상은 조각으로 나눠 보내고 실패한 조각은 다시 보낸다.
- 데스 장면 코칭(선택): 경기 ID(`KR_...`)와 Riot ID(`닉네임#태그`)를 넣으면 Riot 경기 기록으로 내가 죽은 장면을 따로 코칭한다. 서버에 Riot 키가 없으면 입력칸이 잠긴다.
- 분석 진행: 영상 스캔 → 팀 판별 → 장면 선정 → 프레임 추출 → VLM 분석 → 코칭 작성 (→ 데스 코칭) 단계와 진행률. 다른 페이지로 가도 분석은 계속된다.
- 분석 기록: 올린 영상 목록과 상태. 삭제 버튼(페이지 안 확인창)으로 기록을 지울 수 있다. 분석 중인 기록과 예시 경기는 지울 수 없다.
- 예시 경기: 팀이 수집한 리플레이로 미리 만든 분석.

**리포트**

- 요약: 분석 대상 팀, 최종 킬 스코어, 영상 길이, 교전 장면 수, 게임 시계 인식률
- 경기 총평: 총평, 개선할 점, 잘한 점, 다음 경기 전에 연습할 것, 구간별 킬
- 경기 타임라인: 게임 시간 기준 교전 신호와 누적 킬 차트. 장면 구간을 누르면 해당 장면으로 이동
- 장면별 코칭: 교전 패배·승리·킬 없는 교전 필터, 장면 프레임(누르면 확대), 장면 요약·아쉬운 판단·대안 행동(근거 프레임 표시), 검출 이벤트
- 데스 장면 코칭: 데스마다 프레임 8장, 상황, 사망 원인, 근거, 대안 행동, 근거 자료(R: Riot 기록, D: 패치 문서, F: 프레임). 근거가 확인되지 않은 주장은 숨긴다.
- 코치에게 질문하기: 리포트를 근거로 AI가 답한다. 답을 기다리는 동안 '...' 말풍선을 띄운다.

## 사용하는 API

| 메서드 | 경로 | 화면에서 쓰는 곳 |
| --- | --- | --- |
| GET | `/api/config` | VLM·데스 코칭 사용 가능 여부, 업로드 최대 크기 |
| POST | `/api/upload/init` | 업로드 시작 (파일 이름·크기, 선택: 경기 ID·Riot ID) |
| PUT | `/api/upload/{id}/chunk?offset=N` | 조각 전송 |
| POST | `/api/upload/{id}/complete` | 업로드 완료 → 분석 시작 |
| GET | `/api/jobs` | 분석 기록·예시 경기 목록 |
| GET | `/api/jobs/{id}` | 진행 상태, 완료 시 리포트 |
| DELETE | `/api/jobs/{id}` | 분석 기록 삭제 |
| POST | `/api/jobs/{id}/ask` | 코치에게 질문하기 |
| GET | `/files/...` | 장면 프레임 이미지 |

## 실행·수정

따로 실행하지 않는다. Backend 서버를 켜면 `http://localhost:8000` 에서 이 화면이 나온다 (실행 방법은 Backend README).
세 저장소를 같은 상위 폴더에 나란히 클론해야 한다 (`loading/AI`, `loading/Backend`, `loading/Frontend`).

`coach/index.html` 을 고친 뒤 새로고침하면 바로 반영된다 (서버가 캐시하지 않게 설정됨).
배포 서버에는 GitHub에 올린 뒤 Backend의 `deploy/oracle/update.sh` 로 반영한다.
